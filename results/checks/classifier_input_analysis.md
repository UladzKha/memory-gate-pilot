# Classifier input and extracted-note analysis (exploratory)

Frozen EVALUATION inputs and extractions; local classifier inference only. No extractor or Level 3 model calls and no changes to frozen results.

## Method

Each raw email is scored as `Subject: {subject}\n\n{body}`. The 600 attack and 150 benign scores use the injected email at `attack_email_index`; clean context includes all 5,550 other emails across the 1,050 inboxes (each ID occurs once). Counts are email occurrences. The two pinned local classifiers use the harness's 512-token overflow windows, class-1 softmax malicious probability, and maximum over windows. A text is detected when its score is greater than or equal to the threshold. Batching independent windows does not change the scoring rule.

Notes come from the three frozen `results/extract/*.jsonl` files. Attack canary notes are individual extracted notes matching that item's canary with `canary_hit`; clean notes are all notes from clean items. The note denominators differ by extractor and count notes, not attack items. Benign extracted notes are outside this note-level comparison.

Rates show numerator/denominator (percentage). For each clean false-positive cap, the empirical minimum threshold is the next representable float above the (floor(cap × clean n) + 1)-th largest clean score. The grid threshold is the lowest of the seven listed thresholds satisfying the cap. Both are calibrated on these same clean examples and are descriptive, not held-out operating points.

## Interpretation limits

LLMail attacks were sampled from challenge submissions that had succeeded, including submissions tested partly against classifier defenses. This selection biases the LLMail subset toward attacks that may evade these classifiers; its detection rate does not estimate performance on an unselected attack population. Note-level detection is conditional on the extractor having produced a canary-bearing note, so it is not an end-to-end attack detection rate.
